- **Số dư ví**: Σ(transactions) ± Σ(transfers) ± Σ(debt flows)
- **Công nợ**: Receivable = lend − collect − writeOffLend; Payable = borrow − repay − writeOffBorrow
- **Tiết kiệm**: lãi suất đơn (unlimited) vs lãi suất kỳ hạn (fixed term)
- **Chứng chỉ quỹ**: Tính `RATE()` năm hóa từ giá trị hiện tại
- **Quỹ mục tiêu**: Tổng hợp cash + saving + fund_cert → % tiến độ so với target

## 🏗️ **2. 5 NGUYÊN LÝ SOLID — ÁP DỤNG CỤ THỂ TRONG DỰ ÁN NÀY**

| Nguyên lý | Vi phạm nếu KHÔNG áp dụng | Áp dụng trong dự án này (ví dụ code) |
|-----------|---------------------------|--------------------------------------|
| **S — Single Responsibility** | `Wallet` vừa lưu balance, vừa tính interest, vừa export Excel, vừa validate category | `Wallet` chỉ quản lý balance & transactions. `InterestCalculator` tính lãi. `ReportExporter` xuất báo cáo. `CategoryValidator` kiểm tra phân cấp. |
| **O — Open/Closed** | Thêm loại tiết kiệm mới (ví dụ: "Tiết kiệm linh hoạt") phải sửa class `Saving` | `Saving` abstract + `InterestStrategy` interface. Thêm `FlexibleSaving` + `FlexibleInterestStrategy` **không sửa code cũ**. Thêm `PDFExportStrategy` không sửa `ReportGenerator`. |
| **L — Liskov Substitution** | `FixedTermSaving.withdraw()` ném exception → client code dùng `Saving` bị break | `FixedTermSaving` & `UnlimitedSaving` đều implement `withdraw()` hợp lệ (FixedTerm cho rút trước hạn với penalty, Unlimited cho rút tự do). Client code dùng `Saving` reference an toàn. |
| **I — Interface Segregation** | Interface `FinancialInstrument` có 10 method → `Wallet` phải implement `calculateYield()` vô nghĩa | Tách nhỏ: `InterestBearing` (Saving, FundCert), `Transferable` (Wallet), `Freezable` (Snapshot), `Reportable` (all). Class chỉ implement những gì cần. |
