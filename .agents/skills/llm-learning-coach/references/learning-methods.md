# 学习方法论：详细参考

本文是 `SKILL.md` 的支持文件，为 agent 提供两种模式的具体操作细节与呈现形态库。原内容为原创，未复用外部资料。

---

## 1. 模式 A：资料学习的详细流程

### 1.1 文档解析

| 资料类型 | 推荐提取方式 | 注意事项 |
| --- | --- | --- |
| Markdown (.md) | 直接读取 | 保留标题层级与代码块 |
| Word (.docx) | `python-docx` / `pandoc -t markdown` | 注意表格、图片说明、脚注 |
| PowerPoint (.pptx) | `python-pptx` | 每页标题 + 正文 + 演讲者备注；备注常含讲解要点 |
| PDF | `pdfplumber` / `pdftotext` / `pypdf` | 注意分栏、图表；扫描件需先 OCR |

提取完成后，先通读一遍再开始拆解，避免依据碎片信息下结论。

### 1.2 拆解知识点的口径

对每一部分，标注：

- **概念**：定义、术语（中英文）、所属类别
- **原理/机制**：为什么会这样、内部如何工作
- **流程/步骤**：顺序、前置条件、输出
- **公式/参数**：含义、单位、典型取值
- **示例**：具体可运行的例子
- **易错点/边界**：常见误解、例外情形
- **优先级**：`必须掌握` / `需要了解` / `扩展阅读`

### 1.3 呈现形态库（按需组合）

| 形态 | 适用场景 | 输出示例 |
| --- | --- | --- |
| 概念大纲 | 系统性资料 | 层级化目录，每节点一句话定义 |
| 概念图 / 关系图 | 概念间关系复杂 | 文本版节点-连线清单或 ASCII/mermaid 图 |
| 问答卡片 | 记忆型知识 | Q/A 对，含答案与解释，可转制为 Anki |
| 类比与比喻 | 抽象机制 | 用用户熟悉领域的事物类比（标注「类比，非精确对应」） |
| 关键点摘要 | 复习 | 每主题 3-5 条要点 + 一句话总结 |
| 易错点清单 | 巩固 | 常见误解 vs 正确理解对照表 |
| 复习计划 | 长期记忆 | 按 1-3-7-14-30 天间隔排布复习要点 |

### 1.4 讲解节奏

- 一个回合只讲 1 个知识点单元（概念 + 例子 + 一次自测）。
- 自测题形式：选择题 / 填空题 / 「用自己的话复述」。
- 根据作答正确程度调整下一回合深度：
  - 全对 → 加快，进入下一单元；
  - 部分对 → 针对错点补充讲解；
  - 全错 → 换一种解释方式（类比 / 更基础的例子）重讲。

## 2. 模式 B：探索学习的详细流程

### 2.1 澄清目标时问的三个问题

1. 想学什么主题？（具体到概念，如「注意力机制」而非「transformer」）
2. 当前水平如何？（完全没接触过 / 了解概念 / 会写简单代码 / 想深入原理）
3. 期望产出是什么？（理解 / 能实现 / 能向别人讲解）

### 2.2 来源检索与核实的优先级

1. 官方文档（如 Hugging Face、PyTorch、OpenAI 等官方文档）
2. 权威教程与课程（知名大学讲义、公认高质量的博客）
3. 论文原文（arXiv，注意版本与年份）
4. 知名开源项目（GitHub 上 star 高、维护活跃）

核对要点：作者/机构可信度、内容时效（LLM 领域变化快，超过 2 年的资料标注「可能过时」）、是否引用了原始出处。

### 2.3 一次「边探索边学」回合的结构

```
目标 → 来源清单（获认可）→ 单步主题 → 讲解(概念+例子)
     → 用户复述/提问 → 纠偏 → 沉淀一页笔记 → 下一步
```

若遇到不确定的事实，先搜索核实再讲，不要凭印象编造。

---

## 3. 通用校验清单

- 输出的结构是否可扫读（标题、列表、表格）？
- 是否控制每回合信息量（不宜超过 3-5 个新知识点）？
- 自测题是否覆盖本回合核心知识点？
- 外部引用是否可追溯到来源？
- 是否以「下一步」收尾，并等待用户回应？
