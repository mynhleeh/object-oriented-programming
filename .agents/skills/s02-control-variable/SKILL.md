# 控制变量法：提升归因准确率

## R — 原文 (Reading)
> 如果你无法确定一个事件到底是由什么因素造成的，你可以把可能的因素都找出来，然后每次只改变其中一个因素，而控制其余几个因素不变，然后观察这个事件的变化情况。
> — 兰陵王, 第01课

## I — 方法论骨架 (Interpretation)
归因时我们常凭"先后相继"就断定因果，但这是休谟指出的错觉——相关不等于因果。控制变量法把中学物理方法搬来解决这个难题：先把可能导致结果的因素全部列出来，每次只变动其中一个、其余保持不变，观察结果是否随之变化。变了，说明该因素与结果有关；没变，说明无关。如此逐个排除，逼近真实因果构成。它点破了"归纳证明的结构性缺陷"——我们无法 100% 确定因果，但这套方法能大幅提高归因准确率。注意现实里无法绝对控制变量，只能靠大量经验（大数据）近似。

## A1 — 书中的应用 (Past Application)
### 案例 1: 用两个 0 粉账号测爆款标题
- **问题**: 研究爆款文章本质时，如何确认"标题"对爆款的影响程度？
- **方法论的使用**: 同一篇文章用两个 0 粉账号发出，除标题外内容完全一致，对比阅读数据。
- **结论**: 标题变化带来数据剧烈波动→标题是影响爆款的因果之一。
- **结果**: 确认标题作用，并指出"现实无法绝对控制变量"（平台会把文章推给不同的人），只能靠大量经验大致确认。（第01课）

### 案例 2: 复盘中固定变量定因果
- **问题**: 模型树复盘中要确定某因素是否真是因果。
- **方法论的使用**: 保证其他因果不变（选题、封面、开头、内容等），只改变待验因素，看数据是否剧烈变化。
- **结论/结果**: 作为"归因"步骤里提升准确率的标配手段写进模型树操作。（第07课）

## A2 — 触发场景 (Future Trigger) ★
### 用户会在什么情境下需要这个 skill?
1. 判断"是 A 导致结果，还是只是相关"时。
2. A/B 测试、对比实验、运营/产品改版效果归因。
3. 多因素纠缠（如团队业绩下滑因谁、因哪个环节）需要拆解。
4. 反驳"我用了 X 就有效，所以 X 有用"的简单归因。
5. 研究某个干预措施的真实效应。

### 语言信号
- "是它导致的，还是只是相关？" / "is it causal or just correlated"
- "做个对照/AB 测试" / "run a controlled test / A-B test"
- "控制变量" / "control variables"
- "归因错了/到底是哪 factors" / "which factor actually caused it"

### 与相邻 skill 的区分
- 与 `s01-san-gui` 的区别：三归是总框架，控制变量只是"归因"这一步内提升准确率的子方法。
- 与 `s05-review-model` 的区别：复盘中用控制变量来确定因果，但控制变量可独立于复盘用于任何归因场景。

## E — 可执行步骤 (Execution)
1. **找齐因果** — 完成标准：列出影响结果的全部可能因素（认知/领域知识不足时先向外求补全，见 s01 向外求），不遗漏主要变量。
2. **控制变量观测** — 完成标准：每次只改变一个因素、其余保持不变，记录结果变化；变→有关，不变→无关，逐因素排除；判停：若现实无法隔离变量（如平台随机分发），转为"多组大数据近似对比"，并显式标注不确定性。
3. **下结论** — 完成标准：给出"在本观测范围内，X 与结果相关/因果"的限定性结论，注明边界与残留不确定性；开放心态容忍世界的不确定性。

## B — 边界 (Boundary) ★
### 不要在以下情况使用
- 因素本身不可观测或不可操控（如人性底层动机），只能靠向外求（阅读心理学/生物学）补充。
- 只需定性理解、不追求精确归因时，简单关联即可，不必大动干戈。

### 作者在书中警告的失败模式
- 简单归因：凭"前后相继"就断定因果，忽略多因果（见 counter-examples ce18）。
- 误以为写作技巧导致数据好：作者亲历——同规律可由选题/标题/封面等任一造成，无法 100% 确定单一因果（第01课）。

### 作者的盲点/时代局限
- 现实根本无法绝对控制变量，且"有限个例哪怕再多也不能构成证实的基础"（归纳证明结构性缺陷）；作者把因果客观存在当前提但轻带过休谟问题，结论始终是"近似"而非确定（见 BOOK_OVERVIEW 批判段"因果无法 100% 确定"）。

### 容易混淆的邻近方法论
- 与"相关分析/统计显著"混淆：控制变量是实验思想，统计显著不代表因果，仍需机制解释。
- 与"类比"混淆：控制变量求真实因果，类比只是套用相似经验（见 counter-examples ce23）。
