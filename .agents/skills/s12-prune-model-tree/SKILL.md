# 修剪模型树（存量 / 模型 / 结构 三修剪 + 纵/横/跨界 三考察）

## R — 原文 (Reading)

> "修剪模型树才是最重要的，它是整个模型树的灵魂……强大的知识体系，不是一开始就构建出来的，而是长期修剪出来的。"
> "拖延的本质实际上是一种恐惧，一种痛觉……拖延症是一种关于『预期的痛觉』……一旦你狠下来开始去做，即使刚做一点，这种痛觉就消失了一大半。"

— 兰陵王, 第08课（灵魂地位 + 修剪之痛）

## I — 方法论骨架 (Interpretation)

- 种树只是施肥浇水，修剪才是开花结果——前面总装是"快速获取模型"，修剪是"最纯粹的思考"，是整个模型树的灵魂。
- 三大修剪对象：存量（删废句、纠错位）、模型（迭代名字更精确、细化粗糙模型）、结构（关系）。
- 结构三考察：纵向看上下级是否"以上统下"（因果/层次方向一以贯之）；横向看同级是否"同一级、不重不漏、分类归组"；跨界看不同知识体系能否合并、沉淀出更本质的第一原理树。
- 最大的阻碍是"修剪之痛"——但它本质是**预期的痛觉**，不是行动的痛觉；真做起来痛感大减，还会换来"认知飞升"的爽感。
- 这是终身事业：没有一劳永逸，停止输入与修剪，认知就停止成长。

## A1 — 书中的应用 (Past Application)

### 案例 1: 修剪之痛与认知飞升（作者亲历）
- **问题**：很多人知道修剪重要，却一直拖延，体系越来越乱。
- **方法论的使用**：作者研究拖延本质，发现它是"预期的痛觉/恐惧"；用"心狠手辣、立马去做"克服，并主动享受烧脑。
- **结论**：修剪之痛在做之前最强烈，动手即消退；把每次修剪当"认知飞升"机会，从抗拒变上瘾。
- **结果**：作者彻底爱上修剪，每次结构变动都获得"从混乱到有序"的畅快。

### 案例 2: 大修剪中迭代模型 + 修剪存量（作者亲历）
- **问题**：种植时认知不够，摘了无价值句子、放错模型，且模型名粗糙/肤浅。
- **方法论的使用**：年度大修剪时删除无价值句、把放错的句摘出重归位；用存量中重复的关键词迭代模型名，并把粗糙大模型继续细化为更具体的模型。
- **结论**：存量支撑模型迭代；模型须越具体越细致越好，不可为求简洁丢了细节。
- **结果**：模型从模糊到清晰、从宽泛到精细，认知持续升级。

### 案例 3: 跨界考察，建出"战胜树"（作者亲历）
- **问题**：作者分别建了《孙子兵法》的"兵法树"和《定位》的"定位树"，发现两树大量模型重叠。
- **方法论的使用**：做跨界考察，识别出战争与商战被相同法则支配，遂合并沉淀出更本质的"战胜树"，战争树/商战树降为具体场景树。
- **结论**：不同主题知识体系常因共享第一原理而重叠；跨界考察可互相启发、万物互联、收敛出本质树。
- **结果**：从具体场景树抽象出本质"战胜树"，实现一模多用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 模型树里出现大量重复模型、命名混乱，自己都调不出来。
2. 想从"知道很多模型"进阶到"看透本质、收敛到第一原理"。
3. 到了定期（每年）大修剪，或经典书重读后认知升级，需要回看旧树。
4. 多个主题的知识体系明显重叠，想合并、去重、互联。
5. 感觉该沉下心做一段深度思考，但一直被"修剪之痛"拖延。
6. 用户想花一个周末把树彻底修剪完美、之后不用再管——激活以纠正"一次完美不成立，须持续迭代"。

### 语言信号
- "我的知识体系好乱，模型重复" / My knowledge system is messy, models overlap.
- "该大扫除/深度思考一下了" / Time for a deep cleanup / real thinking.
- "这几个概念好像是一回事" / These concepts seem to be the same thing.

- 与 `s11-model-tree-four-steps` 的区别：s11 是"种树"（总装输入），本 skill 是"修剪"（运维思考）。

## E — 可执行步骤 (Execution)

1. **克服拖延，立即开剪** — 完成标准：已坐下来打开笔记软件开始修剪，且感受到痛觉消退。判停：若仍一直拖延，对自己"心狠手辣"逼一把，不跳步——本步无替代方案。
2. **修剪存量** — 完成标准：删掉无价值句（奥卡姆剃刀），把放错模型的句子摘出、重归正确模型。
3. **修剪模型** — 完成标准：把认知提升后看出的错误/肤浅模型名迭代得更精确；把粗糙大模型下还能细分的存量继续提炼为更细模型。
4. **纵向考察** — 完成标准：每个模型的上下级关系正确，因果或层次方向一以贯之（不忽上忽下）。
5. **横向考察** — 完成标准：同级模型确属同级；做到不重不漏（合并/补全重复与残缺）；必要时分类归组（超 4 个则归并）。
6. **跨界考察** — 完成标准：找出本树与其他知识体系重叠处，互相启发；能合并的沉淀出更本质的第一原理树。

## B — 边界 (Boundary) ★

### 不要在以下情况使用
- 树还几乎是空的——先去 s11 总装、积累存量，否则无物可剪。
- 追求"一次修剪就完美"——修剪是终身迭代，早期错误不可避免，后期再纠。

### 作者在书中警告的失败模式
- **修剪拖延症（ce26）**：因"预期的痛觉"一直拖，体系越来越乱；破解法是"立马去做、心狠手辣"。
- **模型粗糙（ce28）**：为求简洁把细节都塞进大模型，丢失可继续提炼的精细模型，认知停在宽泛层。
- **主题阅读不查重复（ce29）**：不同巨人用不同话讲同一知识，不识别就提炼出大量重复模型，阻碍看透真相。
- **害怕犯错不敢动手（ce30）**：等"完全懂了再开始"，导致树永远空白；错误本就可后期修剪纠正。
- **因果方向不贯（ce27）**：体系里忽"因在上"忽"果在上"，造成结构混乱、大量重复模型。

### 作者的盲点/时代局限
- "终身修剪"强度极高（BOOK_OVERVIEW 立场盲点）：作者把多数学习问题归因于"不肯深度思考/不肯修剪"，低估了普通人的执行门槛与时间成本，对碎片化、高压人群适配性弱。
- 把"修剪之痛=预期痛觉"作为通用动力机制，对重度拖延/注意力缺陷人群未必奏效，需配合更具体的习惯设计。

### 容易混淆的邻近方法论
- **单纯整理笔记**：修剪是深度思考（推敲本质、关系、收敛），不是把笔记排整齐、归类归档。
- **s11 总装**：总装是"建"，修剪是"养"；别把初次搭建时的浅思考当成修剪。
